---
name: iPad dashboard branding
description: Confirmed visual constraints for the StecStats iPad dashboard header and player selector
---

Do not place the StecStats logo in a separate full-width strip, centered card, pill, or floating rectangle on the iPad dashboard. Keep branding integrated through the established colors and typography, and keep the player selector inside the scrollable dashboard content below the safe area.

The approved mobile direction translates the desktop dashboard's dense information hierarchy: sharp bordered stat blocks, strong uppercase section labels, orange accents, compact roster chips, and glossy orange-to-black gradients on interactive controls.

Use the classic full-width iPad dashboard: a centered player hero with orange glow, large portrait/name, summary stat cards, full shooting gauges, and playmaking/defense cards below. Do not use a narrow left profile column.

**Why:** The side-by-side layouts produced either an undersized/collapsed profile or a tall empty card. The user explicitly selected the earlier full-width dashboard screenshots as the target.

**How to apply:** On iPad in either orientation, use the full safe-area width with no desktop max-width cap. Stack the centered hero, responsive summary cards, defense cards, and three gauge cards. Keep stat cards flat and use the glossy treatment for buttons.

**Why:** Separate logo treatments looked detached from the interface, while a pinned landscape player row sat behind the iPad status information and made player names appear faded or hidden. The user explicitly confirmed the desktop dashboard screenshots as the preferred visual direction.

**How to apply:** Dashboard changes must preserve safe-area spacing and render player chips in a dedicated high-contrast content row. Prefer flat, information-dense sections over decorative glow/card effects. Do not reintroduce a pinned top-left selector or an independent logo image container.
